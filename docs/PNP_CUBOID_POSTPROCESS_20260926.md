# 八角点之后的可选透视 PnP

日期：2026-09-26。本次新增后处理，没有重新训练或替换模型权重，也没有改变 YOLO。

## 原理和适用边界

网络仍按任务要求接收单张紧裁剪 RGB，输出八个有固定编号的热图。PnP 接在解码之后：

```text
RGB → ResNet-FPN → 八点热图 → 原始二维八点
                                  ↓ 加上已知三维八点、拍摄相机 K 和畸变参数
                         RANSAC PnP → 内点精修 → R,t
                                  ↓
                         同一个三维盒重新投影为八点
```

紧裁剪减少背景对网络的干扰；PnP 利用三维几何减少不一致的角点误差。PnP 本身不读取 RGB，输入图片大部分是目标，不等于它自动获得了焦距或正确角点。虚拟八角点可以落在机身框外，不能将它们强制贴到 YOLO 框四边。

需要的内参属于**拍摄视频的观察相机**，不是画面中被识别的 DJI 相机。裁剪、缩放会改变像素坐标和 K，但不会使未知内参变成已知。

本实现真实帧先将网络输出还原到原图坐标，再使用原图内参。也可在裁剪坐标中求解，但必须使用 `K_crop = A_crop_resize @ K_original`；主点不应直接改成裁剪中心。畸变参数应与输入图像实际状态匹配；已经去畸变的视频不能再次套用原畸变参数，鱼眼模型也不能直接作为普通针孔参数传入。

参考：[OpenCV PnP 文档](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)。标准 PnP 利用 3D–2D 对应关系及内参/畸变求姿态；RANSAC 用于处理离群点。

## 与之前刚体约束的区别

之前 `bop_bb8/rigid.py` 使用的是弱透视 `s·(RX)_xy+t`，将深度/焦距合并到尺度；它没有使用真实透视内参。在有明显透视的图像上，即使用正确八点拟合也会产生近似偏差。

本次新增 `bop_bb8/pnp.py`：

- 固定八点编号与模型三维角点对应，不进行角点任意交换。
- 明确使用提供的针孔 K 和畸变参数；不猜测真实视频焦距。
- `solvePnPRansac` 使用 EPNP、最多 1000 次迭代、confidence=0.999。
- 默认至少 6/8 个内点且其三维布局非退化，再用内点进行 `solvePnPRefineLM`。
- 再检查重投影内点数、数值有效性和全部模型点的正深度。点群塌缩、近共线、内点不足时明确拒绝。
- 不覆盖 RANSAC 的成功标志，不因求解失败强制回退到“总能画一个框”的普通 PnP。
- `accepted` 仅表示给定相机模型下通过几何一致性检查，不能视为姿态正确率。错编号或错误但自洽的八点可能仍然通过。

当前固定阈值为机身长边归一到 256 时的 5 px；原图中按 `5 * max(crop_w,crop_h)/256` 换算。阈值和最少内点数是待验证的工程选择，不是普适最优值。历史 120 实例对照则固定使用原有 256 方形 ROI 中的 5 px，保留其原来的误差口径。

绝对平移的单位和尺度来自三维模型。若生成 GLB 的物理尺度有误，不能将求出的平移直接声称为准确的实际距离。

## 本地实测结果

复用先前 `local_cause_diagnostic_20260923` 中的 **120 个合成验证实例、960 个角点**及保存的原始预测，使用每帧已有的渲染内参。没有重新预测/训练网络，没有使用角点真值求解网络预测的姿态。

| 方法 | 平均误差（原有 256 ROI px） | PCK@5 | 最大单点误差 |
|---|---:|---:|---:|
| 原始 Top-9 八点 | 1.929 | 96.04% | 159.857 |
| 之前弱透视刚体拟合 | 2.550 | 91.35% | 26.061 |
| 本轮透视 PnP + 重投影 | **1.153** | **99.17%** | **8.756** |

120 个实例均通过几何检查，没有删除失败实例；其中 118 个实例的平均角点误差下降，2 个上升。报告同时支持“拒绝计失败”的 PCK 和“拒绝后保留原始预测”的指标，不能只统计容易求解的样本。

另做真值八点输入的纯几何检查，PnP 重投影平均误差约 `3.66e-6 px`。这说明本批渲染投影与实现一致，不是网络预测成绩，也未用于选择预测姿态。

这些是反复使用过的开发验证实例，不是新的独立测试集。结果支持保留透视 PnP，但尚不能证明真实视频会改善，也不能归因于新长方形输入或 ResNet18，因为对照使用的是保存的旧预测。

## 如何接入新训练结果

合成验证在 `scripts/evaluate_single_rgb.py` 的现有命令末尾加 `--pnp`。该脚本从数据中读取已知内参，输出原始八点、PnP 八点、逐例接受状态，以及拒绝计失败和回退原始预测的两组指标。PnP 不接收 GT 姿态或 GT 八点；GT 仅用于计算最终误差。

接口核验使用新网络的一轮小样本 smoke checkpoint，在 16 个合成实例上有 0/16 个通过 PnP，全部记为求解失败。这个模型尚未收敛，该结果说明后处理没有把明显错误点群强行包装为成功结果；它不是正式训练效果。

真实帧通过 `scripts/infer_resnet_yolo_real.py` 显式传入：

```bash
python scripts/infer_resnet_yolo_real.py \
  --checkpoint /absolute/path/to/trained/best.pth \
  --detections /absolute/path/to/fixed_yolo_detections.json \
  --output /absolute/path/to/new_review \
  --models-info /absolute/path/to/models_info.json \
  --pnp-camera /absolute/path/to/observer_camera.json
```

`observer_camera.json` 必须包含：

| 字段 | 含义 |
|---|---|
| `K` | 3×3 原始输入帧针孔内参矩阵 |
| `dist_coeffs` | 对应输入帧的 OpenCV 针孔畸变参数；显式空列表表示零畸变 |
| `image_size` | 与原始输入帧严格一致的 `[W,H]` |
| `source` | 参数来源说明，保留是否标定/近似的事实 |

未提供相机 JSON 时保持原始八点输出，不运行真实帧标准 PnP。存在的 `synthetic_camera.json` 仅用于合成接口测试，**不可当作真实视频内参**。

真实帧输出原始预测仍在 `frames/`；可选 PnP 单独保存到 `frames_pnp/`，并在 `predictions.json` 记录内参来源、重投影残差、内点编号、求解状态。拒绝时不画伪造的规整框。

实际接入真实视频前，应从原始数据集/设备标定找到可信相机模型，或进行相机标定；如果只能使用近似内参，则只能标记为近似几何诊断，不能直接报告准确 6D 位姿。当前未对真实视频运行猜测内参的 PnP。

## 测试与变更范围

新增 `tests/test_pnp.py` 的 6 项检查：准确透视恢复、两个离群点的真实 RANSAC 剔除、非等比紧裁剪内参变换、畸变模型、塌缩/缺失点拒绝、非法内参拒绝。连同现有网络和裁剪等回归检查，共 99 项通过；合成评估和带显式 K 的帧推理入口均已完成短流程核验。

生产变更仅涉及 `bop_bb8/pnp.py`、`scripts/evaluate_single_rgb.py`、`scripts/infer_resnet_yolo_real.py`，以及测试和说明文档。没有新依赖，训练结构、损失和数据不变，因此不因增加 PnP 重新估计或增加训练轮数。
