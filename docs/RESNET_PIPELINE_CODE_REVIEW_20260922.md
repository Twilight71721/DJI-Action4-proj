# 按任务流程审查 ResNet50-FPN、监督与解码

审查范围：三维模型 → HCCEPose/BlenderProc 渲染 → BOP 标签 → 单实例 RGB → 8 通道热图 → 8 角点 → 目标域评估。此次只新增审查材料和可复现检查，不改权重、不改训练数据、不重新训练、不替换生产解码器。不能将完成审查等同于问题已修复。

## 结论与优先级

| 优先级 | 发现 | 性质 | 影响 |
|---|---|---|---|
| P1 | 原划分按动作族隔离且测试全为镜头正面主视角 | 已确认的实验设计问题 | 无法回答训练样本增加是否改善通常意义上的泛化 |
| P1 | 全局 top9 可以将相距很远的峰平均成没有响应的位置 | 已复现的解码设计缺陷 | 错位、对数值扰动和 batch 改变敏感 |
| P1 | 无有效性/不确定性输出，零或不明确热图也强制输出八点 | 接口与推理流程缺口 | 无法区分成功定位和网络没有可靠预测 |
| P2 | decode_topk 分母 clamp_min(1e-8) 破坏小数值热图的尺度不变性 | 已复现的数值代码缺陷 | 极低概率情况下坐标被拉向原点；尚无证据是当前截图主因 |
| P2 | 坐标辅助损失采用空间 softmax 期望；推理采用 sigmoid 全局 top9 | 确认存在的设计差异，非自动等同 bug | 多峰条件下训练优化的坐标与评估坐标不一致，需要消融 |
| P2 | 使用确定性真值框裁剪，未引入框扰动等训练增强 | 训练覆盖缺口 | 对 YOLO 框偏差和输入变化缺乏专门训练；人工框下仍失败，故不是唯一原因 |
| P2 | 当前真实评估没有可靠的 8 点/位姿真值 | 评估缺口 | 只能定性检查，不能声称真实角点精度或 6D 姿态改善 |

## 1. 三维模型、渲染和标签

该任务的八点是固定模型坐标系下三维 AABB 的八个角点投影，不是 RGB 检测框的四角，也不要求位于可见轮廓/真实材料表面。遮挡的角点仍可作为监督；几何 valid 与表面可见性不能混淆。

对固定 2630 帧、5260 个实例逐个比较：从 BOP 的模型角点、R/t、K 投影，与渲染阶段保存的 Blender 世界矩阵独立投影一致，平均差 0.0000894 原图像素，最大差 0.000599 像素。元数据报告所有实例使用同一 mesh、深度均为正；两个模型使用的 models_info 相同。没有发现整体单位、左右坐标系翻转、实例顺序或角点顺序错误。

局限：两路投影仍来自同一场景资产，不能证明三维生成模型与真实相机的物理尺寸/轴定义精确一致，也不能代替重渲染后逐像素校验。HCCEPose 的渲染工具不等于其位姿网络：原仓库主要网络预测前后表面形成稠密 2D–3D 对应，我们这里只借用其渲染工具。

## 2. 数据划分问题有多严重

按渲染元数据的 dominant_view（主可见面）统计：

| 集合 | rear_screen | side_left | side_right | top | front_lens |
|---|---:|---:|---:|---:|---:|
| train，4240 实例 | 1694 | 1024 | 1497 | 25 | 0 |
| val，1000 实例 | 571 | 201 | 228 | 0 | 0 |
| test，20 实例 | 0 | 0 | 0 | 0 | 20 |

这并不表示训练图中绝对看不到镜头的一部分，而是没有镜头正面为主的样本。验证集也未覆盖该方向，无法用验证选择前向视角表现较好的权重。旧 200 张过拟合模型训练时覆盖全部原动作族，新模型没有，不能用分数差归因于数据量。

重建实验应按姿态/动作/主视角分层，同时把同一渲染批次及近重复图片作为整体分配。各集合都覆盖重要视角；稀缺姿态需要更多独立种子的批次。不能仅将 2630 张随机打散，靠相邻帧泄漏得到漂亮分数。小数据与大数据实验还必须共享固定评估集、初始化和训练策略。

## 3. 网络结构是否适合

当前本地 ResNet50-FPN：ImageNet backbone 的 stride 4/8/16/32 特征进行 top-down 融合，stride-4 特征通过卷积输出 8 通道 logits。256×256 输入、64×64 热图，符合流程图中单张 RGB → 八点热图的接口，是合理的单物体基线。24.3M 参数，当前训练实例抽查误差约 1.30 px，也没有明显“网络无法拟合标签”的证据。

不能声称它最适合：没有在有效的统一划分下比较 ResNet、ViT、不同头部和解码器。其八个通道虽共享骨干特征，但没有显式强制八点来自同一个刚体投影；可得到几何不相容的点集。ViT 也不会自动解决分布缺失、监督不一致或解码问题。

BoxDreamer 原方法有参考图像/几何信息和 reference-based point synthesizer；当前单裁剪网络没有这些条件输入，因此是受其八角点表示启发的模型，不是等价复现。原仓库 ResNetWrapper 使用 layer4 特征 hook 与 no_grad，不能直接搬来取代当前可微 FPN。当前独立可训练 ResNet-FPN 方向本身没有因此出错。

建议先保持 backbone，修复划分及数值/可靠性接口，比较 argmax、主峰邻域解码、DARK 类亚像素解码；若仍有遮挡困难，再比较显式角点交互或像素投票架构。PVNet 等投票方法是有文献支持的替代，但改变输出表示，若必须严格遵循 8 张热图的任务约束，不应默默替换。

## 4. 损失和训练

本地以 logits 计算稳定 focal loss，标签在 [0,1]，推理只做一次 sigmoid；未发现与 BoxDreamer [-1,1] 表示混用、重复 sigmoid 或误用 smoothl1 的问题。FPN 可反传，冻结 backbone 时 BatchNorm 留在 eval，这些已有测试覆盖。

辅助 coordinate_loss 取 softmax(logits) 的空间期望，最终解码却是 sigmoid(logits) 上 top9 的加权平均。两者不等价；这是一项需单独实验验证的训练目标选择，不应声称它就是错误根源，也不能在没有对照的情况下同时换 loss、backbone 和数据。

没有对角点联合刚体结构进行显式约束；也没有框 jitter、局部遮挡等针对真实检测裁剪的增强。要新增几何增强，必须同步变换八角点/热图/内参，不能只改图片。cache_data 缓存的是确定性 tensor，不能把随机增强先缓存一次后声称每轮动态增强。

## 5. 解码复现

代码位置：bop_bb8/net/decode.py:30，分母固定下限在第 44 行。

- 单峰在热图 (50,40)，正常返回 (50,40)。全图乘 1e-12 后，同样峰位置返回 (0.005,0.004)。加权均值本应不随正的整体缩放改变，故为确定数值缺陷。
- 全零热图返回有限 (0,0)，下游没有无效标志；真实推理只检查 finite 并画出所有点，不能区分“没预测出来”和“角点在左上角”。
- 等高峰在 (10,10) 和 (50,50)，top2 返回 (30,30)，该位置响应为零。加权不能避免跨峰平均。
- 实际 frame2150/YOLO instance0，top9 在输入坐标中横向跨度可达 168px、纵向可达 180px，输出与 argmax 最远相差约 84.6px。这解释部分点为什么落在不合理的位置，但最高峰本身也可能错。
- 在已观察的测试集上仅换 argmax，误差仍约112.56px，不是一次有效修复，也不能据此选择测试最优解码器。
- 同 batch 的历史输出复现差小于0.000031px；改单张推理时个别测试坐标差14.57px，说明分散峰排序可放大小数值差异。应检查热图的多峰性并控制复现设置，而不是隐藏差异。

建议接口输出 points + 有效性/质量信息。非零热图用数值稳定的相对权重归一化；零/NaN/Inf 输入明确拒绝或标无效；在主峰局部解码时仍报告次峰歧义。局部窗口、拒绝规则和参数只能在验证集上确定；不能把 sigmoid 峰值直接叫校准后的角点正确概率。若需固定八点接口，也应另外输出失败状态，不能拿错误坐标继续当可靠输入。

BoxDreamer 原热图解码是全局 top20 坐标均值，不是我们的 weighted top9；参考原方法并不能证明该解码在当前单图任务上的鲁棒性。DARK 是可供验证的分布感知解码方案，其论文的人体关键点结果不能直接当作本项目收益保证。

## 6. 坐标与最终任务边界

上次抽查 68 实例：训练/推理预处理 tensor 最大差0；OpenCV 独立投影裁剪后与标签差约1.9e-5px；12条边与八点定义匹配；理想目标热图解码平均误差0.642px、最大1.492px。常规离散化误差不足以解释100px级失败，但未证明所有极端裁剪边界都已覆盖。

若目标止于图中的“提取八角点”，当前结构实现了接口但可靠性不足；若要交付 instance-level 6D pose，还需要真实相机内参/畸变处理、2D–3D对应和PnP/鲁棒估计及位姿评估。当前 bop_bb8 主路径没有完成该闭环。PnP成功或较低重投影误差也不等于真实位姿正确。
